# reqforge — 产品手册

> 面向：产品经理、业务人员、最终用户 | 版本：1.0 | 日期：2026-09-13

---

## 1. 产品简介

**reqforge（需求锻造工厂）**让业务人员和产品经理通过**填表单**自动生成 AI 编码工具能直接使用的高质量需求规约文档。一句话：**你不会写 AI 规范文档没关系，填表就行。**

支持的端：Web 网页端 / APP 移动端 / 后端 API

---

## 2. 解决什么问题

### 痛点
用 AI 编码工具（Claude Code、CodeX）时需要编写结构化规范文档，但需要懂 Markdown、懂 VibeCoding/OpenSpec 格式——门槛太高。

### 方案
三步表单引导 → 自动生成规范 `.md` 文件 → 直接丢给 AI。

### 价值对比

| 对比 | 传统方式 | reqforge |
|------|----------|----------|
| 需学 Markdown | 需要 | 不需要 |
| 需知 AI 规范 | 需要 | 不需要 |
| 格式统一 | 靠自觉 | 自动统一 |
| 耗时 | 1-2 小时 | 5 分钟 |

## 3. 核心功能

### 三步表单
| 步骤 | 内容 | 示例 |
|------|------|------|
| Step 1 | 标题、提出人、优先级、日期 | "订单批量导出 Excel" |
| Step 2 | 痛点、影响范围、量化指标、用户故事 | "运营每月汇总耗时 2 天" |
| Step 3 | 验收标准(WHEN/THEN)、约束条件 | "10 秒内下载 xlsx" |

### 自动生成规约
- **VibeCoding**：生成 `TASK.md`（给 Claude Code / CodeX）
- **OpenSpec**：生成完整变更包（.yaml + 多 .md）

### 需求工坊
- 渲染规约 → 预览文件 → 在线编辑 → 保存修订（版本自动递增）→ 导出下载

### 需求管理
- 列表查看 + 状态/优先级筛选 + 搜索 + 附件上传（PNG/JPG/PDF/DOCX，≤20MB）

## 4. 操作指南

### 提交需求（Web 端）

1. 打开 `http://127.0.0.1:8090/requirements` → 点击「提交需求」
2. **Step 1**：填标题(必填)、提出人(必填)、优先级、日期 → 下一步
3. **Step 2**：填痛点(可多条)、影响范围(必填)、量化指标、至少一条用户故事(作为/想要/以便) → 下一步
4. **Step 3**：至少一条 WHEN/THEN 验收标准、可选技术约束/合规要求 → 提交
5. 闸门通过 → 进入工坊 → 选渲染目标 → 生成规约 → 预览/修订/导出

### 用户故事模板
```
作为：{谁需要用这个功能}
想要：{ta 想做什么}
以便：{达成什么目的}
```
例："作为客服专员，想要按日期导出工单，以便不用手工逐条复制粘贴。"

### 验收标准模板
```
WHEN：{什么条件/场景下}
THEN：{应该出现什么结果}
```
例："WHEN 选择日期范围且工单数 > 0 点击导出，THEN 10 秒内下载 xlsx。"

## 5. 关键概念

### 需求状态
| 状态 | 说明 | 可操作 |
|------|------|--------|
| 草稿 | 未提交 | 编辑、提交 |
| 已提交 | 过闸门 | 渲染、编辑 |
| 已导出 | 已下载过 | 重新渲染、重新导出 |

### 渲染目标
| 目标 | 产物 | 适用场景 |
|------|------|----------|
| VibeCoding | TASK.md | 给 AI Agent 直接消费 |
| OpenSpec | .yaml + proposal.md + tasks.md + spec.md | 团队规范化管理 |

### 工件版本
每次渲染 → 新版本(v1,v2...)。改表单后旧工件标"已过期"。在线编辑保存 → 版本递增。

## 6. 常见问题

**Q: 填一半能保存吗？** A: 点「暂存」保存为草稿。

**Q: 提交后发现写错？** A: 工坊页点「编辑表单」修改后重新渲染。

**Q: 生成的 .md 能直接用吗？** A: 可以，直接给 Claude Code/CodeX。

**Q: 提交失败原因？** A: 缺标题/提出人/影响范围/功能/验收标准，或用户故事三要素不完整——系统会列出缺失项。

**Q: 支持手机吗？** A: 支持，有 Flutter APP (Android/iOS)。
