## Purpose

需求工厂 Flutter 移动客户端：以商业应用信息架构（底部五槽导航 + 中央凸起提交键）提供需求的移动端浏览、提交与工坊预览，支持演示数据模式先行、后切真实 API。

## ADDED Requirements

### Requirement: 底部五槽导航

APP SHALL 采用底部五槽导航：需求列表 / 相册式工坊 / 中央凸起「＋提交」/ 记忆（首版为占位空态预告）/ 我的。Tab 切换 MUST 保持各页状态与滚动位置；中央「＋提交」点击进入全屏表单提交流。

#### Scenario: Tab 保状态
- **WHEN** 用户在列表页滚动到第 3 页后切到「我的」再切回列表
- **THEN** 列表仍停留在第 3 页滚动位置

#### Scenario: 记忆占位
- **WHEN** 用户点击「记忆」Tab
- **THEN** 显示 Phase 3 功能预告的空态页，不出现报错或空白崩溃

### Requirement: 演示数据模式

APP SHALL 内置演示数据模式并默认启用：Mock 数据为确定性样例（固定需求清单、状态、md 工件内容），演示模式激活时 MUST 在全部页面顶部显示显式横幅标注。用户 SHALL 能在「我的」页关闭演示模式切换到真实 API，切换后如后端不可达 MUST 给出连接失败与重试指引。

#### Scenario: 演示模式横幅
- **WHEN** 演示模式启用时浏览任意页面
- **THEN** 页面顶部持续显示「演示数据」横幅

#### Scenario: 切换真实 API 失败指引
- **WHEN** 用户关闭演示模式且配置的后端地址不可达
- **THEN** 页面呈现连接失败态与「重试 / 重新开启演示模式」操作，MUST NOT 假装展示真实数据

### Requirement: 需求浏览

列表页 SHALL 以卡片流呈现需求（标题、状态徽标、优先级、提出人、更新时间），支持下拉刷新、滚动分页加载、状态筛选 chips。点击卡片进入需求详情。

#### Scenario: 下拉刷新
- **WHEN** 用户在列表页下拉
- **THEN** 列表刷新并回到第一页，刷新指示器正确出现与消失

### Requirement: 移动表单提交

「＋提交」SHALL 进入全屏分步表单流（与 Web 端三步结构一致：基本信息 → 业务描述 → 验收与约束），支持暂存草稿、字段级校验提示、提交结果反馈。提交成功后返回列表并定位到新需求。

#### Scenario: 移动端提交闭环
- **WHEN** 用户在 APP 完成三步填写并成功提交
- **THEN** 显示成功反馈后回到列表页，新需求出现在列表顶部且状态为「已提交」

### Requirement: 工坊预览

工坊页 SHALL 提供需求 md 工件的只读预览：渲染目标切换（openspec / vibecoding）、工件版本切换、过期标记提示。移动端 MUST NOT 提供双栏编辑（编辑能力归 Web 端）。

#### Scenario: 目标与版本切换
- **WHEN** 用户在工坊页将渲染目标从 openspec 切到 vibecoding、版本从 v2 切到 v3
- **THEN** 预览内容即时切换到 v3 的 vibecoding 工件，无残留缓存内容

### Requirement: 我的页

「我的」页 SHALL 提供：需求统计卡（各状态数量）、后端地址配置、连接自检、演示模式开关、关于信息。

#### Scenario: 连接自检
- **WHEN** 用户在「我的」页点击连接自检
- **THEN** 显示对配置后端地址的健康检查结果（成功/失败与耗时）
