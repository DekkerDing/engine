# document-ingestion — 文档摄取管线规格（delta）

## Purpose

将用户上传的文本文档（txt/docx/pdf）自动转化为分块、向量化、可检索的知识条目，全程状态可查、失败可追溯、删除可联动清理。

## ADDED Requirements

### Requirement: 文档上传与校验
系统 SHALL 接受 txt、docx、pdf 三种格式的文档上传，单文件大小上限 50MB；超出格式或大小限制的上传 SHALL 被拒绝并返回明确错误信息；空内容或无法解析的文件 SHALL 进入失败状态而非静默丢弃。

#### Scenario: 上传合法文档被受理
- **WHEN** 用户上传一个 1MB 的 docx 文件
- **THEN** 系统返回唯一文档 ID 与初始状态"已接收"，文档出现在文档列表中

#### Scenario: 超限文件被拒绝
- **WHEN** 用户上传一个 60MB 的文件
- **THEN** 系统拒绝上传并返回带有原因（超过大小上限）的错误响应，不产生文档记录

#### Scenario: 损坏文件进入失败状态
- **WHEN** 用户上传一个内容损坏的 pdf 文件
- **THEN** 文档记录被创建，状态转为"失败"，失败原因对用户可见

### Requirement: 摄取状态机
系统 SHALL 对每个文档跟踪并暴露状态：已接收 → 解析中 → 已解析 → 向量化中 → 已索引（成功终态）或 失败（失败终态）；每次状态查询 SHALL 返回当前状态、已处理进度（如分块数、已向量化块数）与失败原因（若失败）。

#### Scenario: 状态随处理推进
- **WHEN** 一个可正常解析与向量化的文档完成全部处理
- **THEN** 轮询文档状态可观察到状态依次推进并最终到达"已索引"

#### Scenario: Python 引擎不可达时进入失败态
- **WHEN** 文档处于向量化阶段且 Python 引擎无法在配置的超时时间内响应
- **THEN** 文档状态转为"失败"，失败原因包含下游不可达的信息，已完成的分块结果不丢失

### Requirement: 文本分块
系统 SHALL 将解析出的全文按可配置的目标块长（默认约 400 字符）切分为多个文本块，相邻块之间保留句子级重叠；每个块 SHALL 携带所属文档 ID 与序号，支持回溯到原文位置。

#### Scenario: 长文档产生多块且可溯源
- **WHEN** 上传一篇 5000 字的文档并完成解析
- **THEN** 系统生成多个文本块，每块均可关联到其文档与在文档中的顺序

### Requirement: 向量化入库与降级标记
系统 SHALL 将文本块批量送取向量化引擎并将结果向量持久化；当引擎处于降级模式（真实模型不可用）时，文档与块 SHALL 被显式标记"降级"，且该标记在文档详情中对用户可见。

#### Scenario: 降级模式下的摄取
- **WHEN** 真实模型不可用（引擎返回降级向量）时完成一篇文档的摄取
- **THEN** 文档详情显示降级标记与原因，检索仍可进行但页面提示精度受限

### Requirement: 文档管理与联动清理
系统 SHALL 提供文档列表（含状态、块数、大小、时间的分页查询）、文档详情与删除；删除文档 SHALL 联动清除其全部分块、向量与全文索引条目。

#### Scenario: 删除后不再命中
- **WHEN** 用户删除一篇已索引文档并随即用该文档独有内容发起检索
- **THEN** 检索结果不再包含该文档的任何片段
