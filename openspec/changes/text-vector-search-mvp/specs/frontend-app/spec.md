# frontend-app — React 前端应用规格（delta）

## Purpose

提供全站统一布局与风格的管理界面：仪表盘看全链路健康与调用链、文档管理走完摄取流程、语义检索页验证混合检索效果，让用户"点一页看懂整体调用流程"。

## ADDED Requirements

### Requirement: 标准化布局体系
全站页面 SHALL 遵循统一布局骨架：固定顶栏（应用名/全局状态）+ 固定侧边导航（仪表盘/文档管理/语义检索）+ 内容区栅格；间距、字号、栅格断点 SHALL 全站一致（坐标定位规范），页面之间切换不发生布局跳动。

#### Scenario: 布局一致性
- **WHEN** 依次访问仪表盘、文档管理、检索三个页面
- **THEN** 顶栏与侧边导航位置、宽度保持不变，仅内容区变化

### Requirement: 前端路由
应用 SHALL 提供至少三条路由：/（仪表盘）、/documents（文档管理）、/search（语义检索）；浏览器前进/后退 SHALL 正常工作；任意路由直接刷新 SHALL 恢复原页面（依赖网关 SPA 回退）。

#### Scenario: 浏览器导航可用
- **WHEN** 用户从检索页点击浏览器"后退"
- **THEN** 返回文档管理页且页面状态正确渲染

### Requirement: 文档管理页
页面 SHALL 支持：拖拽/选择上传（展示上传进度与结果）、文档列表（名称、大小、状态徽标、块数、时间，状态自动轮询刷新）、删除（带确认）、详情查看（分块数、向量化模型、维度、降级标记、失败原因）。

#### Scenario: 上传后状态流转可见
- **WHEN** 上传一个文档并停留在列表页
- **THEN** 列表中该文档状态自动从"处理中"推进到"已索引"，无需手动刷新

#### Scenario: 失败原因可见
- **WHEN** 某文档摄取失败
- **THEN** 状态徽标显示"失败"，详情中展示失败原因

### Requirement: 语义检索页
页面 SHALL 支持：查询输入与提交、结果列表（文档名、命中片段关键词高亮、相似度分数、命中来源标注）、命中计数与耗时展示、空结果空态、错误错误态；查询历史 SHALL 在会话内保留可快速重查。

#### Scenario: 检索命中与高亮
- **WHEN** 检索命中包含查询词的片段
- **THEN** 片段中查询词以高亮样式呈现，相似度分数与来源标注可见

#### Scenario: 空结果空态
- **WHEN** 检索无任何命中
- **THEN** 页面展示引导性空态而非空白或报错

### Requirement: 系统仪表盘页
仪表盘 SHALL 展示：三组件健康卡片（网关/业务服务/Python 引擎，含当前通道、模型名、维度、降级原因）、系统关键统计（文档数、分块数）、请求调用链路示意（浏览器→网关→业务服务→Python），数据周期自动刷新。

#### Scenario: 故障组件可视化
- **WHEN** Python 引擎子进程被停止
- **THEN** 仪表盘对应健康卡片在刷新周期内转为异常状态并显示原因

### Requirement: 降级状态全局可见
当引擎处于降级模式时，应用 SHALL 在页面显著位置（全局横幅）持续显示"检索精度受限"提示，直至降级解除。

#### Scenario: 降级横幅出现与消失
- **WHEN** 引擎进入降级模式后用户浏览任意页面
- **THEN** 全局横幅可见；引擎恢复后横幅自动消失

### Requirement: 统一 API 客户端与错误处理
应用 SHALL 通过统一 API 客户端访问后端：统一响应信封解析、请求超时控制、错误统一提示（toast/横幅）；开发态经由开发代理访问网关，生成为相对路径请求，产物不含后端绝对地址。

#### Scenario: 后端不可用统一提示
- **WHEN** 后端返回 5xx 或网络不可达
- **THEN** 页面弹出统一风格的错误提示且不崩溃，用户可重试
