# image-ingestion 规格（批量导入与标注持久化增量）

## ADDED Requirements

### Requirement: 批量导入端点

系统 SHALL 提供批量上传端点：单请求携带多张图片（数量与总体积有明确上限并在超限时拒绝），逐张执行与单张上传一致的黑名单外校验（格式白名单 / 大小上限 / 魔数校验）。校验失败的文件 SHALL 逐文件记录错误并继续处理其余文件，不使整批失败。

#### Scenario: 批量上传部分失败

- **WHEN** 一次批量上传 50 张图片，其中 3 张格式不在白名单
- **THEN** 47 张进入摄取管线，3 张在结果明细中记录各自的拒绝原因，端点返回成功受理明细

#### Scenario: 超出单请求上限被拒绝

- **WHEN** 单请求携带的文件数超过配置上限
- **THEN** 整批被拒绝并返回明确错误与上限值，不做部分处理

### Requirement: 异步导入任务与进度查询

批量导入 SHALL 以异步任务方式执行：受理即返回任务标识，后台按受控并发逐张完成「校验→存储→标注→双向量化」；系统 SHALL 提供任务查询端点，透出任务状态、已处理/总数、成功/失败计数与失败明细（文件名+原因）。任务状态在服务重启后允许丢失（内存态），但已成功入库的图片不受影响。

#### Scenario: 导入进度可见

- **WHEN** 千级照片批量导入任务执行中，客户端轮询任务查询端点
- **THEN** 可观察到已处理数递增、成功/失败计数与失败文件明细

#### Scenario: 服务重启后任务查询

- **WHEN** 导入任务执行期间服务重启，之后查询该任务
- **THEN** 任务报告不存在或终止态，已入库图片仍可正常列表与检索

### Requirement: 摄取管线的标注阶段与第二向量

图片摄取管线 SHALL 在像素路向量化之外增加：结构化标注阶段（产出 subject / description / tags / mocked）与描述文本路向量化（标注文本经文本嵌入模型编码为图片的第二向量）。两路向量 MUST 与图片资产关联持久化，且互不干扰：任一路失败 SHALL 记录原因并保持另一路可用。

#### Scenario: 双向量入库

- **WHEN** 一张携带 caption="红色的小花"的照片走完摄取管线
- **THEN** 该资产同时拥有 CLIP 像素向量与基于标注文本的描述向量，均可在各自空间被检索命中

#### Scenario: 标注失败时像素路不受影响

- **WHEN** 标注阶段失败
- **THEN** 图片完成存储与像素路向量化，描述路向量缺失且记录原因，资产状态可追溯

### Requirement: 上传端点的 caption 参数

单张与批量上传端点 SHALL 接受可选的描述入参（caption）：单张端点为请求参数，批量端点按「文件名→描述」映射或与文件顺序对应的列表提供。入参仅作用于标注构造（见 image-annotation 能力），MUST NOT 影响校验与存储行为。

#### Scenario: 批量上传携带描述映射

- **WHEN** 批量上传携带两个文件与两条对应描述
- **THEN** 两张图片的标注分别采用对应描述构造

### Requirement: 标注元数据的持久化与透出

图片资产 SHALL 持久化标注字段（subject / description / tags / annotation_mocked / 标注来源与时间），存量图片（本变更前入库）标注字段为空并视为"未拆分"。列表与详情 API MUST 透出上述字段；删除图片时标注随资产一并清理。

#### Scenario: 存量图片标注为空

- **WHEN** 查询本变更前入库的图片详情
- **THEN** 标注字段为空（区别于 mocked=true），不报错
